# Mobile release automation

GitHub Actions checks every pull request and `main` push. A push of a tag named
`vX.Y.Z` creates a signed Android App Bundle and signed iOS IPA, uploads the
AAB to Google Play, then sends the IPA to TestFlight.

## One-time setup

### 1. Store the generated signing material

Signing material was generated locally outside this repository in
`~/.offbeat-signing.DuQXRf/`. Follow its `README.md` to put the keystore,
passwords and iOS certificate request in Bitwarden. Never commit them.

Android's upload-key fingerprint is also shown by:

```sh
keytool -list -v \
  -keystore ~/.offbeat-signing.DuQXRf/offbeat-upload.jks \
  -alias offbeat-upload
```

Register the Android upload certificate with Google Play Console when the Play
app is first created. Keep the keystore and both passwords indefinitely: Google
Play uses this key to authenticate all future uploads.

The current upload certificate SHA-256 fingerprint is:

```text
07:46:72:3D:F4:72:56:63:D5:DC:41:C3:36:FC:CB:A7:54:EE:EF:E5:48:B1:52:02:F8:40:13:46:C5:FB:BF:A6
```

### 2. Configure Apple signing

The generated `ios-distribution.csr` is a certificate request, not an Apple
signing certificate. In Apple Developer, create an **Apple Distribution**
certificate with it and create an **App Store Connect** provisioning profile for
`dev.arlyon.offbeat` with the **Associated Domains** capability. Follow the local
README to export the resulting
certificate as a password-protected P12.

Create an App Store Connect API key with the **App Manager** role, download its
P8 file once, and retain it in Bitwarden. The P8 is not generated by this repo.

### 3. Configure Google Play publishing

Create the Play Console app with package name `dev.arlyon.offbeat` and register
the Android upload certificate shown in step 1. Create a Google Cloud
service account, link it in Play Console under **Users and permissions**, and
grant it release access for the app. Download its JSON key once and retain it in
Bitwarden.

The release workflow uploads each tagged AAB plus Play listing metadata, images
and screenshots from `apps/mobile/fastlane/metadata/android` to the configured
Google Play track with `fastlane supply`. Use `internal` first until tester
access and store metadata have been verified.

### 4. Create GitHub `production` environment

In **Settings → Environments**, create `production` and require review before
jobs run. Store these environment secrets there:

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Single-line Base64 of `offbeat-upload.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_ALIAS` | `offbeat-upload` |
| `ANDROID_KEY_PASSWORD` | Key password |
| `IOS_CERTIFICATE_P12_BASE64` | Single-line Base64 of distribution P12 |
| `IOS_CERTIFICATE_PASSWORD` | P12 password |
| `IOS_PROVISIONING_PROFILE_BASE64` | Single-line Base64 of App Store profile |
| `APP_STORE_CONNECT_ISSUER_ID` | App Store Connect API-key issuer ID |
| `APP_STORE_CONNECT_KEY_ID` | App Store Connect API-key key ID |
| `APP_STORE_CONNECT_PRIVATE_KEY` | Complete P8 private-key text |
| `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` | Complete Google service-account JSON |

Set these non-secret environment variables too:

| Variable | Value |
| --- | --- |
| `OFFBEAT_SERVER_URL` | Production HTTPS server URL |
| `OFFBEAT_RP_ID` | Production WebAuthn RP ID, for example `offbeat.app` |
| `OFFBEAT_SERVER_PUBKEY` | Production MainDO Ed25519 public key in hex |
| `ANDROID_APK_KEY_HASH` | Base64url SHA-256 hash for native passkeys |
| `ANDROID_CERT_SHA256` | Android upload certificate SHA-256 fingerprint |
| `APPLE_TEAM_ID` | Apple Developer Team ID for the distribution profile |
| `GOOGLE_PLAY_TRACK` | Google Play target track, usually `internal` first |

The production variables are compiled into the app. They are configuration, not
secrets, but must be correct. Never rely on the development defaults.

Set the repository-level variable `RELEASE_IOS=true` after all Apple secrets and
variables are ready. It must be repository-level because GitHub evaluates the iOS
job condition before loading the `production` environment.

## Release

1. Ensure CI is green on `main`.
2. Update `apps/mobile/pubspec.yaml`'s user-facing version if needed.
3. Create and push an annotated version tag:

   ```sh
   git tag -a v1.0.0 -m 'OFFBEAT 1.0.0'
   git push origin v1.0.0
   ```

4. Approve the GitHub `production` environment deployment.
5. Confirm the workflow uploads the Android AAB to Google Play's configured
   track.
6. Wait for Apple processing, then choose TestFlight testers in App Store
   Connect.

The workflow uses the tag (without `v`) as the iOS and Android version name and
GitHub's monotonically increasing workflow run number as the build number.
Re-running a failed release therefore produces a higher build number.

The push and pull-request workflow validates release configuration without
creating full binary artefacts. Full signed builds only run for version tags.

## Local signed Android build

Do not create `android/key.properties` from shared values. Copy the generated
keystore and create that file only on your machine, then delete it when done:

```properties
storePassword=...
keyPassword=...
keyAlias=offbeat-upload
storeFile=offbeat-upload.jks
```

`apps/mobile/android/.gitignore` excludes both the properties file and keystore.

## Remaining local prerequisites

The workflows run on hosted macOS, so no local Apple tooling is needed to release.
For local iOS builds, install the full Xcode application, select it, complete its
first-launch setup, then install CocoaPods with Homebrew:

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
brew install cocoapods
```

This workstation currently has only Xcode Command Line Tools, so iOS archive
creation cannot be tested locally. The release workflow must be exercised after
Apple signing material is configured.
